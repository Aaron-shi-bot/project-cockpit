## 1. 视觉方向

以瓷白背景承托蓝紫、杏色、薄荷、淡金、天蓝和浅紫面板。主摘要采用蓝紫渐变，其他区域主要使用浅色平面。深墨色标题与大号数字建立阅读顺序，柔和阴影、精细圆角和稳定间距提供层次。产品名称由用户明确为“项目驾驶舱”；图中轨道标识继续沿用。完整名称不得省成旧名；小侧栏可缩小字标或使用上下组合，避免挤压主内容。

新版同时调整布局：窄导航减少占位；项目总览从横向表格改成三列彩色面板；详情仍用白色任务表方便比较。最重要的信息是进度与任务基数，卡点集中右侧；近期日期形成底部横向清单。颜色、数字与空间共同建立层级，而不是平均给每个区域加亮色。

“炫酷”通过有限的渐变、明确的色块、轻盈的层次和流畅反馈表达。保留充足留白，不增加无依据的健康分、炫光雷达或动画背景。

## 3. 配色有两个不同用途

**项目身份色**便于在总览与详情中认出同一项目：控制台浅紫、客户门户桃色、数据工作台薄荷、移动改版天蓝、知识库淡金、待启动项目白色。同一项目在所有页面保持相同身份色，项目身份色不会随健康状态自动改变。

**状态语义色**单独表达正常/完成、风险、阻塞与待开始。状态必须配文字；不能把“桃色项目”理解为“所有桃色都受阻”。紫色用于选中与进行中，绿色用于正常或已完成，深红用于受阻，深赭用于风险。浅色背景上的数字采用较深的文本色；亮珊瑚、亮绿等适合进度条与装饰，不作为小字颜色。

颜色、尺寸、阴影与渐变唯一维护在 design-tokens.json。主摘要渐变只承载短标签与数字；白色字所在区域要保持足够对比。表格、长说明、表单输入区采用平色。输入框边界用 controlBorder，细分隔线用 divider，不能混用。

## 4. 排版、轮廓与图形

中文使用本机微软雅黑，保留 Noto Sans SC / 苹方回退；数字使用等宽数字特性并对齐。页面标题、区块标题、项目标题和进度数字形成四级层次。正文不小于14 CSS px，注释12 px只用于低优先级说明。

面板建议20 px圆角、控件12 px；白色内容区使用极轻投影，不把所有彩色面板做成悬浮玻璃。项目进度条有对应数字与分子分母。顶部5/6分段环明确表示“6个项目中5个进行中”，不是健康评分或任务完成率。详情45%环表示9/20任务完成，两种指标标题必须保留。

图标采用一致的线条与少量选中态实心形，最终界面使用可维护SVG。文件图标可用不同类型色，但必须保留文件名与类型，避免只靠颜色。概念标识与图形待方向确认后提取或矢量化，不裁切整张截图充当界面。

## 5. 布局与响应式

桌面参考1600×1000。窄侧栏约100 CSS px；主区弹性；三列项目面板+右侧关注栏。每张面板顺序固定：名称/状态、阶段、进度与基数、进度条、下个里程碑。长项目名允许两行，状态不截断。

- ≥1280：三列项目面板；当可用宽度不足时优先将关注栏上移，保证单卡宽度。
- 768–1279：两列项目面板，关注事项成为上方横区；任务表仅表格自身滚动。
- <768：单列项目面板；摘要采用一大两小；风险前置；四项底部导航。手机概念是可滚动长页，示例只展示两个项目并提供“查看全部6个项目”。
- 触摸目标至少44 px。底部内容留出导航高度和安全区。最终移动图已增加末尾留白，避免入口被底栏遮挡。

手机下个里程碑保留日期与项目，不铺开横向时间轴。桌面底部是三件事的顺序清单，不按连线距离推算工期。

## 6. 组件与关键状态

| 组件 | 默认表达 | 状态规则 |
|---|---|---|
| 主按钮 | 蓝紫实底或短渐变，白字 | hover轻提亮，focus外圈，提交中禁重复 |
| 筛选 | 浅紫或白底，选中用深紫文字/实色 | 同时有边界或底色变化，键盘可操作 |
| 彩色项目面板 | 身份色底、深色文字、清晰进度 | hover轻抬升；整卡可打开；不常驻过多按钮 |
| 状态标签 | 浅语义底+深语义文字 | 正常/受阻/有风险/待启动明确写出 |
| 风险提示 | 浅红条、原因与受影响日期 | 靠近任务，不反复弹窗或闪烁 |
| 更新表单 | 当前进展、下一步、健康状态 | 不手填完成率；失败保留输入；成功局部提示 |
| 空/错误状态 | 清楚文字+一个可执行动作 | 空项目引导新建；无任务显示未拆任务；失败重试 |

加载时使用与布局同尺寸的浅色骨架，不以0%代替未知数据。网络失败保留上次数据并标注更新时间；无权限提供返回。关闭未保存表单前提醒。动效限定hover、抽屉、保存反馈；遵循减少动态效果设置。实际键盘/触摸/读屏待开发阶段验证。

## 7. 业务事实与样例

原有业务目标、来源和统计建议继续引用PRD。六个项目中五个进行中、一个待启动；需关注两个；今天起七天内里程碑三个。客户服务门户9/20=45%，已完成9、进行中7、待开始3、受阻1；表格只展示5条。验收清单在任务表和里程碑侧栏均为待开始。

任务条数完成率是本项目建议。飞书原件中的项目进度按关联需求数计算，不能混为同一个已确认算法。资料已核实的组织方式继续保留，颜色重设计不改变统计事实。
