# 002 云端数据与提交边界

日期：2026-10-23。本文件补充部署模型；既有业务实体与校验继续引用[001数据模型](../001-team-cockpit/data-model.md)及[唯一业务接口合同](../../server/contract.md)，不复制另一套完整字段定义。实际表定义以 `站点/project-cockpit/db/schema.ts` 和受版本管理的 `drizzle/` 为准。

| 对象 | 云端保存内容与关系 | 不变量 |
|---|---|---|
| 既有业务实体 | 项目、任务、里程碑、风险、进展、评论、成员、团队、授权及版本，逐行持久保存 | 保留ID、对象version、作者、日期和既有枚举；不靠浏览器或Worker内存长期存储 |
| 初始化状态 | 单例工作区建立状态、首位所有者与建立时间 | 初始未建立；只有有效一次凭据能从未建立→已建立；不能回到未建立 |
| 身份安全记录 | 密码派生值、会话、邀请凭据摘要、失败限流及幂等记录 | 不存明文密码或邀请秘密；个人改密撤销其他会话，管理重设撤销该用户全部会话，停用/退出按既有规则撤销；每次幂等重放先重新鉴权 |
| 全局revision | 一次完整快照的持久提交序号 | 写入按读取时revision竞争；至多一个竞争者提交全部差异；失败不写部分审计、授权或业务 |
| 文件版本引用 | D1版本行→私有R2不可变对象key、大小及识别元数据 | 用户文件名仅是下载元数据，不构成路径；旧版字节不覆盖；删除业务记录不暴露字节 |
| 文件清理队列 | 尚未归入有效版本的对象引用与可重试清理状态 | 只能删除未被已提交版本引用的孤立对象；重试不会破坏历史版本 |
| 发布信息 | 站点ID、构建/保存版本、部署ID与网址 | 只保存非秘密标识；实际平台结果与业务验收分开 |

## 一次写入的边界

1. 从当前有效会话及primary快照确定权限、对象版本与业务规则。
2. 在请求内计算实体差异和审计，不共享可变Map给其他请求。
3. 必要时先上传不可变私有文件；数据库未确认前不让新版本出现在业务读取中。
4. 通过revision条件保护的单次batch提交业务差异、相关风险、审计、初始化消费状态或幂等结果。条件不满足时全部业务差异不得提交，返回明确冲突。
5. 失败时撤销/排队清理尚无有效版本引用的字节；成功后按持久版本读取响应。下一请求重新读取权限，不沿用先前授权缓存。

这是一项必须通过并发与失败注入验证的设计约束，不是D1/R2跨服务原子事务的声明。内存SQLite模拟、本地Worker和实际线上分别验证，结果记入单一验收记录。

## 迁移与保留

- 迁移为静态schema-only SQL，不携带本机数据、预置所有者、演示项目、密码或会话。
- 已应用迁移不可原位改写；新增迁移处理后续变化。请求处理中不动态创建或修改表。
- 不新增自动永久删除历史、审计或回收站的策略。孤立文件清理只处理明确无引用的失败残留。
- 业务项目导出仅含既定元数据，不是D1和R2完整备份；未实测完整恢复前不得宣称已有灾难恢复能力。
