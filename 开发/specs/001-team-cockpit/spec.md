# Feature Specification: 项目驾驶舱团队协作核心

**Feature Branch**: `001-team-cockpit`（功能标识；当前无 Git 仓库，未创建分支）

**Created**: 2026-10-23

**Status**: 本机核心已实现，设计验收与专项验证进行中；Sites适配未开始。实施缺口和测试状态以任务及验收记录为准。

**Input**: 用户要求沿用已确认明亮彩色 VI 和平台手册，按 project-spec-design-build 顺序推进；多人团队、完整权限；内置账号和邀请加入。后续U-08指定使用Codex Sites，U-09要求先完成设计验收，当前暂不发布。

业务主文件为[PRD](../../../需求/PRD.md)，设计依据为[平台手册](../../../设计/平台设计手册.md)和[视觉规范](../../../设计/视觉规范.md)。本规格只细化 REQ-001—013 的功能切片；REQ-014—019 保持待评审候选。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后掌握项目并推进任务 (Priority: P1)

负责人或成员登录后，在同一屏识别自己可访问项目的进度、阶段、风险和近期里程碑，进入项目后更新任务、阻塞和进展。系统保存团队共用数据，并明确失败、权限变化和修改冲突。

**Why this priority**: 直接实现“项目驾驶舱”的日常价值，是后续资料与协作管理共同依赖的业务入口。

**Independent Test**: 建立首位所有者和一个私有项目，添加任务、里程碑及独立风险；从总览进入详情，把任务标受阻后恢复，重启后查看结果。无需文件或邀请功能即可完成该路径。

**Acceptance Scenarios**:

1. **Given** 用户仅获两个项目的角色，**When** 查看总览、项目、跨项目任务和搜索，**Then** 所有名称、数量和筛选都仅包含这两个项目。对应 AC-03、19。
2. **Given** 有权编辑的任务，**When** 填写原因标为受阻，再填写处理说明恢复，**Then** 任务关联阻塞同步创建和关闭，独立风险继续影响健康状态。对应 AC-14—17。
3. **Given** 项目没有有效任务或仅完成1/3，**When** 查看进度并取消、删除或恢复任务，**Then** 分别显示“未拆任务”或向下取整的比例，基数按同一规则变化。对应 AC-18。
4. **Given** 同一记录已被他人更新或项目已完成/归档，**When** 使用旧表单保存，**Then** 显示冲突或只读说明，不能静默覆盖或绕过生命周期。对应 AC-23、25、26。

### User Story 2 - 保管项目资料和连续版本 (Priority: P2)

有项目权限的成员在资料中心上传文件或保存链接，阅读当前及历史版本；维护者能恢复旧内容和管理回收站，撤权立即影响后续下载。

**Why this priority**: 让团队围绕同一项目保管资料，同时防止文件外泄和旧版本丢失。

**Independent Test**: 在测试夹具中直接提供已有项目角色，上传两个版本、下载历史、恢复旧版；撤权后重试旧下载地址。无需团队或邀请界面即可验证。

**Acceptance Scenarios**:

1. **Given** 同一逻辑资料已有v1/v2，**When** 维护者恢复v1，**Then** 新增当前版本，v1/v2内容和记录保持可追溯。对应 AC-27。
2. **Given** 只读成员可访问项目，**When** 下载当前和历史文件，再被撤权，**Then** 原先允许下载，撤权后的同一地址拒绝访问。对应 AC-28。
3. **Given** 协作成员上传过一份资料，**When** 维护本人资料或尝试改他人资料、删除与恢复，**Then** 本人维护范围有效，维护者专有动作被拒绝。对应 AC-29—32。

### User Story 3 - 邀请团队并让权限可解释 (Priority: P3)

工作区所有者和管理员邀请成员、维护团队；项目维护者给成员或团队授权。操作者能看见权限来源，安全撤权、停用与交接，查看自己管理范围内的审计。

**Why this priority**: 在已具备业务路径后完成多人加入和日常管理。此优先级只表示管理界面的交付顺序，服务端权限隔离属于所有故事的前置条件。

**Independent Test**: 使用两个空项目和隔离账号夹具，完成复制邀请、加入、团队授权、撤销与停用。无需任务或文件内容即可验证角色效果。

**Acceptance Scenarios**:

1. **Given** 工作区管理员没有项目角色，**When** 请求项目内容或自行提升角色，**Then** 不获得内容，也不能自我提升。对应 AC-03—05。
2. **Given** 同一成员同时具有直接和两个团队来源，**When** 依次撤销，**Then** 最高有效角色随来源变化，界面显示仍存来源，最后来源移除后失去访问。对应 AC-06、07。
3. **Given** 邀请到期、撤销、已接受或邀请人失去权限，**When** 尝试接受邀请，**Then** 明确失效，不重复创建成员或增加角色。对应 AC-08。
4. **Given** 最后维护者遭紧急停用，**When** 所有者在说明原因并再次认证后接管，**Then** 停用先撤权，接管后才建立维护权限并记录审计。对应 AC-09—12、33。

### Edge Cases

- 新工作区只允许一次建立首位所有者；两个并发初始化不能产生重复所有权（AC-01、11）。
- 未授权对象与不存在对象使用一致提示，文件历史、统计、搜索和审计均不能绕过范围（AC-03、28、33）。
- 未分配且本人创建的任务允许创建人更新状态；离开受阻时同样必须提交处理说明，只关闭该任务关联阻塞（AC-14—17）。
- 同日不同里程碑分别计数；今天到第6天为七天范围；逾期单列，无日期不误判（AC-20、21）。
- 任务全完成不自动完成项目；完成需有效任务、里程碑和风险满足条件及摘要；归档恢复保留原生命周期（AC-22—24）。
- 上传失败不可见，历史不覆盖，重试不重复创建；旧修改须明确冲突（AC-25、27、30）。
- 手机仍可撤权；键盘弹层焦点和失败草稿可恢复；退出或撤权后不保留可读业务缓存（AC-26、36、37）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供内置账号登录、退出、一次性首位所有者建立；停用或退出立即阻止原会话后续访问。（REQ-011；AC-01、02、09）
- **FR-002**: 系统必须仅按有效项目授权展示并计算总览、搜索、项目、任务、资料及业务审计；工作区管理角色不得隐含项目内容访问权。（REQ-001、009、011；AC-03—07、19）
- **FR-003**: 成员必须能在策略允许时创建私有项目；创建者为维护者，负责人需具维护权限；项目拥有目标、阶段、日期、身份色和独立健康状态。（REQ-003、011；AC-13）
- **FR-004**: 系统必须提供单层任务、里程碑、进展与风险；关联对象只能属于同项目；任务字段编辑按角色及本人负责/本人创建未分配的范围限制。（REQ-003、004、009；AC-14、24）
- **FR-005**: 任务受阻必须有原因并同步关联阻塞；离开受阻必须有说明并同步关闭该任务阻塞。独立项目风险关闭由维护者处理；健康状态按未关闭阻塞优先、风险其次汇总。（REQ-002、004；AC-15—17）
- **FR-006**: 进度必须按完成有效任务/全部有效任务计算，取消和软删除排除，完成任务保留；向下取整，空分母显示未拆任务，100%不自动关闭项目。（REQ-005；AC-18、22）
- **FR-007**: 系统必须按当前权限和筛选范围统一计算关注项目、进行中项目与七天内里程碑；计划日期与完成事实分开，同日多项不合并。（REQ-001、005；AC-19—21）
- **FR-008**: 项目完成必须校验有效任务、里程碑、风险及完成摘要；已完成或归档业务只读，权限撤销仍可执行；恢复和重开明确区分。（REQ-012；AC-22—24）
- **FR-009**: 系统必须提供项目私有文件与HTTPS资料链接，保留逻辑资料的连续、不可覆盖版本；只读成员可下载历史，恢复由维护者执行，撤权影响后续下载。（REQ-010；AC-27—32）
- **FR-010**: 系统必须将所有者/管理员/成员与项目维护者/协作者/只读者分层，显示直接和团队来源，取最高有效角色，保护唯一所有者及最后有效维护者。（REQ-011；AC-04—07、10、11）
- **FR-011**: 系统必须提供有到期时间、收件身份和范围的单次邀请，接受时重校邀请人能力；停用不删除历史作者，保留交接和显式应急接管路径。（REQ-011；AC-08—12）
- **FR-012**: 系统必须持久保留业务数据和文件；软删除与恢复重新检查权限和关系；关键审计追加记录且不包含密码、会话凭据或文件正文。（REQ-010—012；AC-31、33、34、38）
- **FR-013**: 系统必须拒绝静默覆盖，明确修改冲突；同一提交重试不重复创建；失败保留输入并准确报告成功、失败或权限失效。（REQ-004、012；AC-25、26）
- **FR-014**: 界面必须沿用已确认明亮彩色视觉和四项主导航，支持手机、键盘、200%缩放、明确焦点与错误；新工作区不默认载入演示数据。（REQ-006、008；AC-35—37）
- **FR-015**: 系统必须提供可复现的运行、初始化与备份恢复说明，区分本机、浏览器、构建和真实云端验证，不能把业务导出当作系统备份。（REQ-012、013；AC-34、38—40）
- **FR-016**: 需求、视觉、接口及实施差异必须可追溯；REQ-007和013沿用已交付设计；REQ-014—019未经范围决定不作为本轮必须交付功能。（REQ-007、013；AC-40）

### Key Entities *(include if feature involves data)*

- **工作区与成员**：一个工作区、唯一有效所有者，成员具有管理角色与状态；账号可有会话与一次性邀请。
- **团队与项目授权**：团队分组成员，项目给成员或团队授固定角色；有效权限由全部有效来源汇总。
- **项目与执行记录**：项目包含单层任务、里程碑、风险和进展，均有稳定身份、作者、日期与修改版本。
- **资料与版本**：逻辑资料属于项目，拥有不可覆盖的历史版本；文件访问继承当前项目权限。
- **审计与回收记录**：记录重要动作及软删除恢复关系，不随业务软删除消失。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一个有效账号能从登录完成“总览→项目→任务受阻→恢复→总览更新”完整路径，退出并重启后记录仍在；US1场景全部满足。
- **SC-002**: AC-03—12与AC-28的全部负面授权场景中，未授权请求均不能读取或改变受保护内容；管理身份、历史版本和旧页面均无例外。
- **SC-003**: AC-18—21全部统计样例得到确定一致的分子、分母、范围和日期结果；列表与摘要不相互矛盾。
- **SC-004**: 同一资料的两个历史版本及恢复后的新版本都可独立核对，旧内容没有覆盖；失权后同一下载地址不可继续使用。
- **SC-005**: AC-15、16、23、25、31中失败、重试或冲突不会留下半成品、重复对象、悬空引用或静默覆盖。
- **SC-006**: 在390px、768px、1440px和200%缩放下，核心路径及撤权可完成；纯键盘路径焦点可见且弹层关闭后返回触发处。
- **SC-007**: 干净环境按运行指南可完成初始化、业务写入、重启及恢复检查；交付记录分别列出已验证与未验证的本机、构建、浏览器和云端状态。
- **SC-008**: 本轮全部P0验收项有明确结果，未通过项进入任务并修复；P1未完成项和候选范围在交付中明确列出，不误报完成。

## Assumptions

- 采用单工作区与固定角色，团队规模和最终并发容量尚未承诺；初始规模样本是验证输入，不是性能结论。
- 用户选择内置账号邀请，并在U-08将部署目标从自有云服务器改为Codex Sites；按U-09先完成设计验收。当前Node/SQLite本机路径与Docker备用配置不能作为Sites已适配的证明，Workers/D1/R2适配与目标环境重验属于后续切片。
- 邀请先由管理者复制链接传递，不接自动邮件；接受时校验邀请绑定邮箱与凭据，不能声称验证邮箱所有权。受邀者设自己的密码；个人改密需原密码，管理重置需再次认证并审计，无公开后门。
- 停用覆盖访问但保留授权记录；重新启用仅恢复尚存授权的有效性，明确撤销的来源不重建。界面启用前明示效果。
- 有任务状态编辑权者可按说明解除该任务产生的阻塞，包括本人创建且未分配的任务；独立项目风险仍由维护者关闭。
- 附件实际限制可配置；保留周期未定时不执行自动永久清理。仅提供手动业务回收与显式恢复，云端备份目标在部署配置中确定。
- 本规格明确要求关键负面场景自动测试和核心浏览器验收；详细用例见[验收计划](../../../验证/验收计划.md)。测试不是对性能、邮件送达或生产部署的替代证明。
