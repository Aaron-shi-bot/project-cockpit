# 研究与实施决定

日期：2026-10-23。依据现行 PRD、手册、用户关于云端和登录的答复、已安装官方技能、package.json及接口合同进行本地技术评审。下列是实现选择与边界，不是生产容量或云端实测结论。

| Decision | Rationale | Alternatives considered |
|---|---|---|
| 使用 Node24 内置http/sqlite/crypto，单服务负责认证、授权与业务事务 | 与现有骨架一致，减少服务依赖，单库内可原子更新任务、风险和审计 | 独立API框架与ORM增加首版依赖；外部BaaS需要账号与第三方配置。本轮不采用 |
| React19 + Vite7实现已确认VI，生产静态资源由同一服务提供 | 支持复杂状态、表单和管理页；同源降低Cookie和部署配置复杂度 | 静态HTML不足以维护完整团队流程；额外SSR服务没有本轮必要性 |
| SQLite WAL保存业务关系及文件BLOB，私有数据目录挂载持久卷 | 小团队单实例易于备份；同事务写资源版本和字节不会留下分离的半成品 | 对象存储适合后续大文件；PostgreSQL适合多实例和更复杂查询，暂不增加运维组件 |
| 登录用随机会话Cookie，HttpOnly/SameSite；生产Secure；写入CSRF和同源检查 | 客户端不能伪造授权；避免把长期登录凭据写入浏览器业务缓存 | 不用前端自签角色、固定演示口令或浏览器本地“假账号”；令牌不放URL |
| 口令使用随机盐与scrypt，登录失败限流；再次认证保护所有权转移和接管 | 内置账号需要真实口令保护，管理敏感动作不能只依赖已打开页面 | 不存明文口令，不以邀请码作为永久口令；暂未接企业SSO |
| 所有读取与下载每次计算当前有效角色；团队/直接授权取最高有效角色 | 停用或撤权后旧页面和旧地址不能继续访问 | 隐藏按钮、预生成公开文件地址、仅登录时缓存权限都不能达到要求 |
| 乐观锁version和幂等operationId，事务内校验并写入 | 明示冲突且避免响应丢失后的重复提交 | 不采用最后写入覆盖；浏览器草稿不是持久化主数据 |
| 默认单文件10MiB，JSON/base64上传，浏览器无离线写入承诺 | 与当前合同匹配且足够支撑首版验证；真实上限须在界面展示 | 分块上传、大文件预览和杀毒服务需要后续专门设计，当前不宣称具备 |

## 明确的交叉规则选择

1. **停用与重新启用**：停用撤销会话并覆盖全部访问，不删除历史作者或授权记录。再次启用只使仍存在的授权重新有效，已经明确撤销的来源不重建。启用界面须提示这一效果。
2. **未分配自建任务**：有任务状态编辑权的协作者，可在离开受阻时提交处理说明并原子关闭该任务产生的关联阻塞；包括本人创建且仍未分配的任务。独立项目风险和他人阻塞不能借此关闭。
3. **邀请与账号恢复**：管理员复制单次、到期的高熵邀请链接，数据库存凭据摘要；不发送邮件，不声称验证邮箱所有权。个人改密校验原密码，管理重置需再次认证并审计；无公开所有者找回后门。唯一所有者忘密的受控运维恢复需要在部署文档中明确，不能假装邮件找回已接通。
4. **保留周期**：回收站、历史版本和审计不自动永久清理。实际容量与备份位置可配置，最终保留周期后续确定；不把未答复变成删除授权。

## 生命周期与存储边界

归档前生命周期必须保存。恢复归档回到归档前状态；若原状态为已完成，业务仍只读，须显式重开。撤权与管理授权不受业务只读限制。已完成任务重开由维护者执行。

数据库运行时采用WAL，不能在服务仍写入时仅复制主sqlite文件就声称完整备份。首版运行文档应提供停服务后复制整个DATA_DIR并在隔离目录恢复的方法，或使用一致性快照工具。恢复演练必须检查账号、授权、文件字节与版本引用；业务导出不代替备份。

HTTPS反代与Secure Cookie是云端运行配置要求。当前没有域名、云主机或真实证书验收结果；这些环境条件不阻止本机实现，但不能写成已部署。

## 尚未形成承诺的事项

团队容量、并发和性能指标；公网域名与证书；异地备份目标；邮件/SSO/杀毒；大文件与高级预览；自动清理周期。它们不影响本轮已界定切片，均不使用占位假实现冒充接入。

REQ-014—019保持候选。当前Risk的可选字段或项目改期原因可服务已有风险记录和审计，不据此声称交付验收、周会、保存视图、完整基准管理或预设功能已经采纳。
