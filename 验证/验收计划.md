## 2. 数据准备与判定方式

验收使用隔离的测试工作区和临时私有存储，不使用真实成员、密码或客户资料。至少准备：工作区所有者 O、管理员 A、有效普通成员 M、只读成员 V、待停用成员 D、两个团队 T1/T2；项目 P1/P2/P3 分别形成维护、协作、只读及完全无权的交叉关系。O/A 不默认获得 P3 业务权限。

每条权限用例同时检查界面和直接 HTTP 请求；隐藏按钮不能算通过。以持久化数据、响应内容、当前权限和审计为准。匿名请求应要求登录；无权读取对象与不存在对象使用统一提示，不暴露名称、文件大小或版本列表；在已知可读项目上禁止的动作可明确提示权限不足。校验失败不得改变数据；并发版本过期应返回 409 或等价、明示的冲突结果，不能静默覆盖。

优先级 P0：会导致越权、丢数据、错误授权或核心路径不可用，交付前必须解决。P1：业务完整性、异常反馈、视觉与可访问性，交付时逐项给出实测或明确缺口。

## 8. 需在规格中消除的交叉规则

下列是评审建议，不能只在测试文件里偷偷决定：

1. **停用再启用**：手册要求不恢复“已移除授权”；建议停用只撤销会话并覆盖所有访问，不删除授权记录；重新启用仅使尚存授权重新有效，明确撤销的授权不会重建。实施选择应写回规格并在启用界面提示。
2. **未分配自建任务的阻塞**：手册允许创建人编辑本人创建且未分配任务的状态，又仅明确“本人负责”时可关闭关联阻塞。建议凡有该任务状态编辑权者，在离开受阻时提交处理说明并原子关闭该任务产生的关联阻塞，独立项目风险仍由维护者关闭。
3. **邀请身份校验**：内置账号未接邮件时，邀请凭据和邮箱匹配可以验证邀请条件，不能证明邮箱所有权。凭据应高熵、到期、单次使用，数据库不存可直接滥用的明文凭据；密码重置若未实现，须列明恢复方式，不能留隐藏后门。
4. **保留周期**：附件容量、回收站/历史/审计周期未定时，可配置并展示实际限制；不能自动永久删除数据，再把该默认值写成用户已同意。

验证顺序：AC-01—12身份与权限 → AC-13—26项目任务闭环 → AC-27—34文件与恢复 → AC-35—40浏览器、运行与交付。代码测试、HTTP实测、浏览器实测及真实云端检查分别记结果；未接云端时交付可运行配置并准确注明状态。
